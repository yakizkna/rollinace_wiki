# Rollin' Ace 游戏操作指南

> 本文档为智能体提供完整的 Rollin' Ace 棒球骰子游戏操作指南，涵盖所有游戏模式、基本操作、道具系统和各场景玩法。

---

## 一、游戏概述

Rollin' Ace 是一款**棒球骰子网页小游戏**，核心玩法是复刻真实棒球名局的**一个半局**（通常为"九局下半"），玩家扮演**进攻方**，通过掷骰子和使用道具来逆转比分。

### 核心机制

- **服务端权威**：所有掷骰概率、局面推进、过关判定、道具扣减、发奖均在服务端（边缘函数）执行，前端只负责渲染和发送请求
- **身份系统**：基于 HMAC-SHA256 签名的 HttpOnly cookie（`ra_token`），前端不持有 uid
- **双骰博弈**：主骰（4 类结果）+ 二选一骰（高风险分支），加上 6 种道具的战术博弈

## 二、基本操作

### 2.1 掷主骰（Roll）

点击「Roll」按钮掷出第一颗骰子（主骰），结果由服务端按权重随机决定：

| 骰面 | 权重 | 结果 |
|---|---|---|
| OUT（出局） | 2 | 出局数 +1 |
| FOUL（界外球） | 1 | 无影响，重新掷主骰 |
| 1B（一垒安打） | 2 | 打者上一垒，跑者推进 1 垒 |
| 1B/?（模糊面） | 1 | 触发**二选一**决策 |

**归一化概率**（FOUL 重掷后）：OUT 40%、1B 40%、1B/? 20%。

### 2.2 二选一决策

当主骰掷出 `1B/?` 时，玩家需从两个选项中选择：

**选项 A：「拿下 1B」（保守）**
- 直接获得一垒安打，安全上垒
- 安打率更高（60%）

**选项 B：「放手一搏」（激进）**
- 掷第二颗骰子，进入高风险高回报分支：

| 骰面 | 权重 | 结果 |
|---|---|---|
| DP（双杀） | 1 | 打者 + 最靠本垒跑者出局（2 出局前）；2 出局后仅打者出局 |
| BB（保送） | 1 | 打者上一垒，跑者推进 1 垒 |
| 2B（二垒安打） | 2 | 打者上二垒，跑者推进 2 垒 |
| 3B（三垒安打） | 1 | 打者上三垒，跑者推进 3 垒 |
| HR（本垒打） | 1 | 所有跑者 + 打者回本得分，垒清空 |

**归一化概率**：DP 16.67%、BB 16.67%、2B 33.33%、3B 16.67%、HR 16.67%。

### 2.3 好坏球打席（BS 模式）

可选开关（默认关闭），开启后每个新打席先进入好坏球阶段：

1. 玩家选择「打（swing）」或「看（read）」
2. 服务端掷好坏球骰（6 面）：

| 骰面 | 权重 | 选「打」结果 | 选「看」结果 |
|---|---|---|---|
| 红中好球（strikeH） | 2 | 击中 - 进主骰 | 看错 - 好球 +1 |
| 刁钻好球（strike） | 1 | 挥空 - 好球 +1 | 看错 - 好球 +1 |
| 擦边坏球（ballH） | 1 | 击中 - 进主骰 | 看对 - 坏球 +1 |
| 偏出坏球（ball） | 2 | 挥空 - 好球 +1 | 看对 - 坏球 +1 |

3. **打席结算**：
   - 好球 >= 3 -> **三振出局**
   - 坏球 >= 4 -> **四坏保送**（打者上一垒，跑者推进）
   - 击中 -> 自动衔接主骰掷骰（使用更偏安打的权重 1/1/2/1）
   - 未满 -> 继续选「打/看」

**关键性质**：无论选「打」还是「看」，每球好球 +1 的概率恒为 50%。

### 2.4 过关与失败

- **过关（passed）**：比分反超（我方 score > 对方 score），半局立即结束
- **失败（failed）**：满 3 出局未反超

## 三、道具系统

### 3.1 道具总览

| 道具 | 名称 | 类型 | 描述 | 骰面分布（1~6） |
|---|---|---|---|---|
| bat | 棒 | 被动 | 安打自动升级一级（1B->2B->3B->HR） | 不掷骰 |
| steal | 盗 | 主动 | 一垒跑者盗二垒 | 成功x4 / 失败x2 |
| sac | 牺 | 主动 | 牺牲打：垒上跑者各进一垒，打者出局 | 成功x4 / 失败x2 |
| mist | 雾 | 主动 | 防守方失误，随机发生 | 捕逸/暴传/暴投/无事x2/Nice Play |
| lun | 抡 | 主动 | 盲炮选手，高风险大回报 | OUTx4 / 三垒打x1 / 本垒打x1 |
| ling | 令 | 主动 | 传令：成功则重置本局技能使用次数 | 成功x3 / 失败x3 |

### 3.2 使用规则

- **每局最多使用 3 个技能**，同种技能本局不能重复使用
- **令的刷新机制**：成功后重置使用次数为 3 并清空已用集合，所有道具恢复可用
- **背包上限**：每种道具最多 20 个，总上限 120 个

### 3.3 使用条件

| 道具 | 使用条件 |
|---|---|
| 棒 | 无（选中后随主骰自动生效） |
| 盗 | 一垒有人、二垒空 |
| 牺 | 两出局前且垒上有人 |
| 雾 | 无 |
| 抡 | 无 |
| 令 | 本局已使用过至少 1 次技能 |

### 3.4 好坏球模式下的技能限制

- **BS 打席进行中**：只有「盗」可用，其余主动技能禁用
- **棒**为被动始终生效（好坏球击中后主骰 1B 同样升级为 2B）
- 雾/牺/抡只能在**打席未开始**时使用，用后直接结算打席并绕过好坏球流程

### 3.5 道具效果明细

**棒（bat）**：
- 主骰安打自动升级：1B->2B、2B->3B、3B->HR
- OUT/DP/BB 等不生效
- 无论打席以何种方式结束都消耗

**盗（steal）**：
- 成功（4/6 = 66.67%）：一垒跑者盗上二垒
- 失败（2/6 = 33.33%）：一垒跑者出局

**牺（sac）**：
- 成功（4/6 = 66.67%）：垒上所有跑者各进一垒（含回本得分），打者出局
- 失败（2/6 = 33.33%）：打者出局，垒包不变

**雾（mist）**：

| 面 | 效果 |
|---|---|
| 1 捕逸 | 垒上跑者推进 1 垒；无跑者则无影响 |
| 2 暴传 | 垒上跑者推进 2 垒；无跑者则无影响 |
| 3 暴投 | 垒上跑者推进 1 垒；无跑者则无影响 |
| 4-5 无事发生 | 局面不变 |
| 6 Nice Play | 垒上有人则双杀；垒上无人则打者出局 |

**抡（lun）**：

| 面 | 效果 |
|---|---|
| 1-4 OUT | 打者出局（66.67%） |
| 5 三垒打 | 跑者各进三垒，打者上三垒（16.67%） |
| 6 本垒打 | 打者及所有跑者回本得分（16.67%） |

**令（ling）**：
- 成功（3/6 = 50%）：重置本局技能使用次数 = 3，清空已用集合
- 失败（3/6 = 50%）：无效，仅消耗本次使用

### 3.6 道具获取途径

| 途径 | 奖励 |
|---|---|
| 新用户初始赠送 | 各 3 个（由环境变量控制） |
| 普通通关（逆转成功） | 6 选 4，各 1 个 |
| 再见本垒打（HR 且过关） | 棒 3 / 抡 3 / 盗 2 / 牺 2 / 雾 2 / 令 2 |
| 单独本垒打（未过关） | 棒 2 / 抡 2 |
| 3 OUT 局末（失败） | 加权随机送 1 个：盗/牺各 20%、棒/抡/雾/令各 15% |

## 四、游戏模式

### 4.1 挑战赛（普通模式 / 今日挑战）

**页面**：`client/index.html`

**玩法**：
1. 进入主游戏页，系统自动下发当前挑战（由管理端发布）
2. 初始局面：通常为九局下半，我方落后，N 出局，特定垒包配置
3. 目标：通过掷骰子和使用道具，使比分反超
4. 反超即过关（passed），满 3 出局未反超则失败（failed）

**特点**：
- 每日/每期由管理端更新挑战局面
- 过关后可获得道具奖励
- 支持好坏球开关（默认关闭）
- 是最基础、最核心的玩法模式

**API 流程**：
1. `GET /api/challenge` -> 读取今日挑战 + 完成状态
2. `POST /api/roll` -> 掷骰 + 局面推进
3. `POST /api/challenge` -> 完成挑战上报

### 4.2 锦标赛（系列赛模式 / Series Mode）

**页面**：`client/series.html`

**玩法**：
1. 系列赛由管理端配置，包含**多场**单场挑战
2. 从第一场（第 0 场）开始，按顺序闯关
3. 每场需**比分逆转**（我方 scoreMe > scoreOpp）才算赢
4. 任一场未逆转则**整个系列赛结束**
5. 全部场次逆转通过则系列赛**通关**
6. 刷新页面或重进：从已通过的最高场次之后继续（续玩）

**特点**：
- 多场闯关，全部场次逆转通过则系列赛**通关**
- 与普通挑战**完全隔离**（独立 KV 存储、独立进度）
- 系列赛对所有人可见（白名单机制已取消）
- 每场可配置独立的队名、比分、出局数、垒包、局数等
- 支持道具奖励配置（管理端可为每场单独配置奖励卡）
- 活动时间窗控制（管理端设定开始/结束时间）
- 每场通关人数独立统计

**单场配置示例**：
```json
{
  "id": "stage-0",
  "title": "第一场",
  "teamMe": "烤鱼的小屋",
  "teamOpp": "对手队",
  "scoreMe": 2,
  "scoreOpp": 5,
  "outs": 1,
  "bases": [false, false, false],
  "inning": 9,
  "isBottom": true,
  "winCondition": "reverse"
}
```

**API 流程**：
1. `GET /api/series` -> 读取系列赛定义 + 玩家进度 + 白名单状态
2. `POST /api/roll` -> 掷骰 + 局面推进（与普通模式共用引擎）
3. `POST /api/series action=progress` -> 上报进度

### 4.3 无尽战（无尽模式 / Endless Mode）

**页面**：`client/endless.html`

**玩法**：
1. 挑战「几乎不可能完成的比赛」——大比分落后的极端局面
2. 复用普通模式的掷骰引擎
3. 本局我方最终比分即「得分」，计入排行榜
4. 目标：争取最高分，上榜比拼排名

**特点**：
- 排行榜系统：前 100 名（存储），展示前 20 名
- uid 打码显示（前 8 位 + `****`）
- 存储与普通/系列赛完全隔离
- 支持历史战绩联动（最高分 + 最好名次）

**API 流程**：
1. `GET /api/endless` -> 读取活动定义 + 排行榜 + 用户成绩
2. `POST /api/roll` -> 掷骰 + 局面推进
3. `POST /api/endless action=progress` -> 上报成绩、刷新排行

## 五、其他场景

### 5.1 速报房（比赛速报 / Report）

**页面**：`client/report-viewer.html`（观众端）

**概述**：
- 比赛实时转播场景，由**后台程序/脚本**通过 API 创建与控制
- **只可观看**，无主播掷骰玩法
- 复用直播房间 KV 结构（`type:'report'`）

**核心特性**：
- R/H/E 记分牌（安打/失误自动累积）
- 垒包状态实时渲染
- 事件日志（投打对决、安打、出局等）
- 支持直播/重播两种模式
- 状态机：`created` -> `live` -> `ended` -> `closed`；`live` <-> `paused`；任意 -> `cancelled`

**观看方式**：
1. 从直播大厅进入（速报房间标 `type:'report'`）
2. 观众端通过 `GET /api/live` 增量拉取事件帧
3. 支持语音播报（TTS）：中文走腾讯云大模型语音合成（需管理端配置密钥），日文走浏览器本地语音
4. 加入时返回当前局面快照（`situation`），无需回放全部历史帧即可渲染当前局面

### 5.2 直播房（互动直播 / Live）

**页面**：
- 大厅：`client/live.html`
- 主播端：`client/solo-room.html`（自定义挑战）
- 观众端：`client/live-viewer.html`

**概述**：
- 主播一人挑战（九局下半逆转局），多人围观
- 主播操作局面并逐帧 publish，观众只读镜像

**主播操作流程**：
1. 在对战大厅（`/duel`）创建「自定义挑战」
2. 设定初始局面（队名、比分、出局、垒包）
3. 进入 `solo-room.html` 开播
4. 掷骰/使用道具 -> 逐帧 publish 同步给观众
5. 支持弹幕互动

**观众操作**：
1. 直播大厅选择房间 -> 点击「观看」
2. 自动增量拉流（2.5~3 秒轮询）
3. 可发弹幕（需管理端开启 `allowChat`）
4. 手动「刷新」按钮全量拉取最新帧

### 5.3 挑战房（自定义挑战 / Solo Room）

**页面**：`client/solo-room.html`

**概述**：
- 与直播房共用同一套逻辑（`live.js` PAGE_MODE=host）
- 主播创建自定义局面并挑战，观众通过直播大厅观看

**创建流程**：
1. 对战大厅 -> 「自定义挑战」浮层
2. 填写：我方名（随机）、对方队伍（随机）、初始比分/出局/垒包
3. 必须 `scoreOpp > scoreMe`（九下逆转设定）
4. 可选择是否开启直播
5. 进入 `solo-room.html` 开始

### 5.4 对战房（Duel / PvP）

**页面**：
- 大厅：`client/duel.html`
- 房间：`client/duel-room.html`

**概述**：
- 主队 vs 客队的 PvP 比赛
- 支持 1~9 局制，攻守轮换
- 客场先攻

**完整流程**：

1. **创建**（主队）
   - 在对战大厅点击「创建对战」
   - 设定预设局数（1~9）、是否开启直播
   - 房间状态：`matchStatus=waiting`

2. **客队加入**
   - 在大厅点击「加入对战」
   - `matchStatus=live`，比赛开始
   - **客场先攻**

3. **比赛进行**
   - 当前进攻方掷骰/使用道具 -> 上报一帧
   - 防守方与观众只读镜像
   - 每半局 3 出局后换边
   - 上半局结束 -> 下半局（主队攻）
   - 下半局结束 -> 下一局上半（客队攻）

4. **延长赛**
   - 超过预设局数仍平分 -> 延长赛
   - 0 出局、一、二垒有人

5. **比赛结束**
   - 主队下半局反超 = 再见，立即结束
   - 客队上半局不停止（打完整半局）
   - 进攻方宣布胜负 -> `matchStatus=ended`
   - 30 秒后自动关房（由 GET/list 惰性触发）
   - 双方玩家心跳均超时也会自动关房（兜底机制）

**同步机制**：
- 全员每 2.5 秒轮询增量帧
- 无 WebSocket，纯轮询
- 局面快照兜底（防止缺帧停在旧局面）

## 六、历史战绩系统

### 6.1 跨模式战绩记录

**API**：`GET /api/history`

**存储**：`ra_user_history_{uid}`（KV，独立于用户主 KV 和背包）

**记录内容**：

| 模式 | 字段 | 说明 |
|---|---|---|
| 普通挑战 | `challenge_mode_data.succ_ids` | 通关的活动 id 列表（去重） |
| 系列赛 | `series_mode_data.win_ids` | 夺冠的系列赛 id 列表（去重） |
| 无尽模式 | `endless_mode_data.highest_score` | 历史最高分 |
| 无尽模式 | `endless_mode_data.best_rank` | 历史最高排名 |
| 对战 | `duel_mode_data.wins / losses` | 累计胜/负场次 |

- 返回时自动解析活动 id 为活动名称（从 KV 定义读取 `title`），找不到则回退为 id
- 无尽模式：创下更高分或更高排名时更新，并记录对应的活动 id

## 七、音乐与声音系统

### 7.1 音效

- Web Audio 程序化合成，零外部素材
- `master` 总线控制

### 7.2 BGM 曲库

- mp3 格式，管理端上传存储于 EdgeOne KV（`rollinace_music_library` / `rollinace_music_item_<id>`）
- 分两个主题：`classic`（经典）和 `endless`（无尽）
- 每主题最多 10 首，单首 ≤ 10MB

### 7.3 场景槽位

每个主题三个槽位，各指定**一首**曲目：

| 槽位 | 触发时机 |
|---|---|
| `always`（全程） | 进入页面即播 |
| `idle`（空闲） | 点 Roll 之前 |
| `playing`（局中） | 点 Roll 之后 |

- **互斥规则**：全程与空闲/局中不可共存；空闲与局中可并存
- **局中自动降音量**：每主题一个系数（0.2~1.0，默认 0.5），0.3s 渐变，只降 BGM、音效不受影响
- **iOS 限制**：需首次用户手势才能出声（浏览器自动播放策略）

### 7.4 语音播报（TTS）

- 中文：默认走浏览器 `speechSynthesis` 本地免费语音；管理端配置腾讯云密钥后走云端高质量语音
- 日文：始终走浏览器本地语音
- 管理端 `admin_media.html` 配置中文 TTS 音色

## 八、功能开关与守卫

### 8.1 站点配置（`rollinace_site_config`）

| 开关 | 缺省 | 影响 |
|---|---|---|
| `allowLive` | `true` | 直播大厅 + 直播观看页 |
| `allowReport` | `true` | 速报大厅 + 速报观看页 |
| `allowDuel` | `true` | 对战大厅 + 对战房 + 挑战房 |
| `allowChat` | `false` | 弹幕输入区 |
| `showTtsBtn` | `false` | 速报直播间语音播报按钮 |
| `musicEnabled` | `true` | 游戏音乐总开关 |
| `ttsVoiceZh` | `""` | 中文 TTS 音色 ID（空=免费本地语音） |
| `wxArticleUrl` | `""` | 公众号文章链接 |

### 8.2 双重守卫机制

- **前端守卫**：页面加载时经 `feature-guard.js` 检查，开关关闭则跳转专用 `404.html`（白名单用户不受限）
- **后端守卫**：`/api/live` 按房间类型检查开关，关闭且非白名单时直接 403，不初始化、不向 yakisite 拉取任何数据
- 关闭直播/速报/对战后，其余全部功能（掷骰、挑战、系列赛、无尽、战绩等）正常运行，完全不依赖 yakisite

## 九、棒球规则要点

### 9.1 出局与半局结束

- 3 出局 = 半局结束
- 三振、双杀、牺牲打失败等都会增加出局数

### 9.2 跑者推进

- 安打按垒数推进跑者（1B 推进 1 垒、2B 推进 2 垒、3B 推进 3 垒）
- HR（本垒打）：所有跑者 + 打者全部回本得分
- **反超即停止**：比分反超后，后续回本跑者不再得分（HR 除外）

### 9.3 双杀（DP）

- 2 出局前：打者出局 + 离本垒最近的跑者出局（2 人出局）
- 2 出局后：降级为普通 OUT（仅打者出局）

### 9.4 保送（BB）

- 打者上一垒
- 垒上跑者逐个推进 1 垒

## 十、界面元素说明

### 10.1 主游戏页

- **记分牌**：显示双方比分、局数、出局数
- **垒包图**：显示一二三垒占垒情况
- **骰子区**：主骰 + 第二颗骰子（二选一时显示）
- **道具面板**：6 个技能格，显示库存和使用状态
- **好坏球灯**：3 个坏球灯（绿）+ 2 个好球灯（黄）
- **结果区**：显示本次掷骰结果文案
- **操作按钮**：Roll / 拿下 1B / 放手一搏 / 打 / 看

### 10.2 模式切换

- 主页通过 `#modeTabs` 切换「普通挑战」/「系列赛」
- 无尽模式独立页面 `endless.html`
- 对战/直播/速报从各自大厅入口进入（受功能开关控制）
- 首页入口按钮：「播」（直播）、「报」（速报）、「战」（对战），受 `allowLive`/`allowReport`/`allowDuel` 控制
